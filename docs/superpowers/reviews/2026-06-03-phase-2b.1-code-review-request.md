## Please verify (read the code + `BE/openapi.json` + existing Phase 2b patterns)

**A. Correctness vs BE contract.**
1. All 6 `agentApi` methods + `botApi.rotateWallet` use correct openapi paths/verbs/bodies. External revoke must send the agent **name** (not address) in `ExternalRevokeRequest.agent_name` and the `external-revoke-payload?agent_name=` query.
2. `useAgentRevokeFlow`: payload→`eip712Sign(provider, walletAddress, signPayload)`→submit; nonce via `extractNonceFromSignPayload`; app-managed (by id) vs external (by name) branches submit to the right endpoints; error mapping mirrors `useAgentSignFlow` (UserRejected/NoProvider/generic).

**B. ⚠️ Render-loop safety (highest priority — we already hit one here).** The `ManageAgentsModal` test originally **hung** from an infinite render loop (a test mock returned fresh hook refs each render, re-firing the open-effect whose deps included `resetRevoke`). It was fixed at the test level (`4552938`), and production `useAgentRevokeFlow` returns stable `useCallback` refs. **Please audit all `useEffect`/`useCallback` deps in `ManageAgentsModal.tsx`, `AgentOnboardingDialog.tsx`, `WalletChip.tsx`, `LaunchpadModal.tsx`** for any remaining instability that could loop in production (unstable object/array/fn deps; effects that `setState` then re-trigger themselves; the post-revoke-success effect that calls `loadData()` + `onRequestOnboarding()`; the onboarding `onSuccess`→re-open-ManageAgents→rotate path). Confirm none can loop or double-fire on real (non-mocked) hooks/props.

**C. Real-money / destructive-action safety.** Revoke and rotate-wallet have on-chain / bot-restart side effects. Verify: the active-agent revoke shows the stronger confirm before signing and can't be bypassed; you can't accidentally revoke the wrong row (id vs name mapping in the merge); rotate-wallet surfaces `error_count > 0` (failed bots) rather than silently succeeding; nothing auto-revokes/auto-rotates without explicit user action.

**D. Merge logic.** `ManageAgentsModal` merges `hyperliquidWallets()` (on-chain) ⨉ `list()` (DB) by address (case-insensitive). Check: app-managed vs external tagging is correct; revoked/inactive DB rows handled sanely; empty/loading/error states.

**E. Entry-point wiring.** `WalletChip` + `LaunchpadModal` both mount `ManageAgentsModal`/`AgentOnboardingDialog` — no double-mount/z-index/focus-trap issues between nested Radix dialogs; `onManageAgents` optional-prop wiring; the cap-full → manage → onboard → rotate flow is coherent.

**F. Cross-cutting.** Type safety (no `any`); the `isAgentCapFull` string-match fragility (acceptable v1 per follow-up?); tests verify real behavior (not just mocks) and every test COMPLETES (no hangs); the untyped `{ sign_payload: unknown }` revoke-payload typing.
